# USB Flash Disk (`/NAND:` — GLIM/animation assets)

The board's ~6.9 MiB FAT volume (`/NAND:`) is how GLIM assets and `.llext` extensions get onto the
device. This page is the by-hand procedure; `/provision-device` automates it
(`fw/scripts/provision-device.sh`). Firmware-side facts (the patched flashdisk driver, the flash
layout, the MSC LUN): `.claude/rules/fw-storage-usb.md`.

This is exclusive-write access to the board's disk — **hold the `board` lock first** if doing this
by hand instead of via `/provision-device` (which enforces it). The hook can't catch an ad-hoc
`mount` command — this remains convention-only.

## Setting up GLIM files on a new board

All GLIM assets are generated by in-repo Python scripts — nothing is checked in as a binary.
Generate them before provisioning (from the repo root):

```bash
. scripts/tools-env.sh   # Pillow/numpy/lz4 + yt-dlp/ffmpeg; no-op in the devcontainer
python3 fw/tools/generate_nyan_cat_glim.py --output fw/nyan_cat.glim
python3 fw/tools/convert_bad_apple.py --output fw/bad_apple.glim   # downloads from YouTube, ~1 min
# 4096 "greatest hits" (issue #96) — canonical LZ4-compressed GLIM (format 4):
python3 fw/tools/convert_video_to_glim.py --url "https://youtu.be/e9DfSCk-6Ko" --output fw/4096.glim --fps 24 --lz4
```

Then copy all three into `/NAND:/glim/` on the board and reset (this works on macOS too —
`.claude/skills/flash-and-verify/references/macos-host.md`). Other footage: `fw/tools/convert_video_to_glim.py`
/ `fw/tools/convert_gif_to_glim.py`; the player picks new files up at boot
(`.claude/rules/fw-animations.md` "GLIM player"). If the NAND disk on a new board is unformatted or corrupt
(FAT read errors in dmesg), rebuild it with the firmware's own `fatfs reformat` (below) — the
firmware owns the partition, and that is the documented, tested path. A host-side
`mkfs.vfat -F 12 -s 8 -S 4096 /dev/sdX` is a last resort for a disk the firmware cannot reformat, and
**only the user runs it** (it is destructive; the destructive-command hook denies `mkfs`).

## Finding and mounting it from the devcontainer

```bash
# It enumerates as a SCSI disk alongside the container's own disks — identify it
# by the SCSI string, not a fixed /dev/sdX (the letter shifts based on what else
# is attached).
dmesg | grep -A2 "RGB-SG"       # confirms detection, e.g. "scsi 1:0:0:0: Direct-Access RGB-SG FlashDisk"
lsblk                            # cross-reference the ~6.9 MiB size to find the device node, e.g. /dev/sdg
blkid /dev/sdg                   # TYPE="vfat" confirms it's the right one

mkdir -p /mnt/sunglasses-fs
mount -o rw /dev/sdg /mnt/sunglasses-fs
cp bad_apple.glim nyan_cat.glim 4096.glim /mnt/sunglasses-fs/glim/
sync
umount /mnt/sunglasses-fs
rmdir /mnt/sunglasses-fs
```

`.llext` extensions go to `ext/` on the same volume.

**The board will not see new/changed files until it's reset.** After unmounting, reset via mcumgr
(`mcumgr --conntype serial --connstring dev=<mcumgr port>,baud=115200 reset`), `kernel reboot warm`
on the shell, or a physical reset — the firmware's own FAT mount has to be re-established, and both
registries (GLIM and extensions) scan at boot only. Wait ~15 s for the ports to re-enumerate, then
re-run `/check-hardware` before issuing more serial commands.

## FAT concurrent access causes read corruption

The firmware mounts the FAT volume at boot and caches cluster allocations. If you write a file over
USB while the firmware still has the volume mounted, the firmware's in-memory FAT doesn't know about
the new cluster chain — subsequent reads return stale data (wrong CRC, wrong file content). Always
write via USB → sync → umount → **reboot the device** before reading the file from firmware. A warm
reboot (`kernel reboot warm`) is sufficient; no J-Link needed. This also applies to `mcuboot.bin`
staging and to deleting coredumps with `coredump-fetch.sh --delete`.

## Reformatting the NAND filesystem from the shell

Use `fatfs reformat` (requires `CONFIG_FILE_SYSTEM_MKFS=y`, already on for proto0). This is the
correct fix for FAT corruption. Afterwards reboot the board and re-copy any files you need.
